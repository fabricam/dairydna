# Quickstart: Historical Replay

1. Generate a multi-day synthetic dataset (Demo page or `POST /api/generation-runs`); the thin-slice
   profile spans `2025-10-01`–`2025-12-29` with dense data every day.
2. Open `/replay`, paste or pick the generation id, and load the dataset. Use the day scrubber (or
   Previous/Next day) to step through the dataset's date range.
3. If no replay exists yet for the selected day, click **Run replay** — this runs
   `CreateOptimizationRunHandler` for that as-of date (default `Spot` pricing), records an
   independent leakage audit, and stamps the optimizer/costing/model versions used.
   `POST /api/replay/runs { generationId, asOfDate, priceMode? }`.
4. The replay summary shows status, objective (contribution margin), leakage pass/fail, and the
   model/optimizer/costing versions; the network map and top recommended movements reuse the demo
   summary and optimization-run APIs for that as-of date.
5. Build a regret report for a date window (`POST /api/replay/reports/regret { generationId,
   startDate, endDate }`): each day replays (if needed) and is compared against two baseline
   policies — nearest-customer-first and highest-price-first — using the same allocation inputs.
   The comparison renders as a grouped-bar chart (total contribution margin: optimizer vs. each
   baseline) plus a per-day win/lose table. The report explicitly states whether the optimizer met
   the bar (beat both baselines) on at least one day in the window.
6. A sample regret-window report for the demo dataset is checked in at
   `specs/012-historical-replay/fixtures/regret-window-sample.json` (regenerated by
   `ReplayServiceTests.Regret_report_fixture_is_written_for_the_demo_window`).

Replays and regret reports are demo/portfolio features — baseline "actual outcomes" are proxy
economics computed from the synthetic dataset, not a claim of historical market performance.
