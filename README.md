# DairyDNA

Decision-support and logistics optimization demo for dairy milk and cream
allocation across a synthetic U.S. dairy network.

DairyDNA forecasts supply, demand, and prices; estimates transportation cost;
and recommends the highest-value **feasible** product movements.

## Honesty boundary — read this first

- **This is a demo/portfolio project, not a production system.** No real
  trades, no real truck dispatch, no production-grade market advice.
- **All data is synthetic**, generated by a seeded random data generator
  (`DairyDNA.DataGenerator`), optionally textured with a handful of real
  *public reference* series — never live trading or proprietary data.
- **Recommendations are suggestions, not instructions.** They are OR-Tools
  optimizer output over the synthetic dataset — nothing has been dispatched.
- **Local-dev only, unauthenticated.** There is no login, API authentication,
  or tenant isolation. Do not expose this to the public internet or use it
  with real business data. The browser map uses a restricted Google Maps
  JavaScript API key as described below.
- Full detail: [`docs/demo/honesty-boundary.md`](./docs/demo/honesty-boundary.md).

## One-command demo

```powershell
cd c:\repos\dairydna
dotnet restore DairyDNA.sln
dotnet run --project src/DairyDNA.AppHost
```

Or use the wrapper script, which restores/builds first and prints the URLs
and next steps: `./scripts/demo-start.ps1` (add `-InMemory` to skip Docker
Desktop/SQL Server and run the API standalone with an in-memory database).

Open the Aspire dashboard link printed in the console, then the **web** and
**api** endpoints. On the demo home page: Generate → Load demo summary → Run
optimization → View recommendations. For the full labeled walkthrough
(network map, charts, recommendations, scenarios, replay) follow
**[`docs/demo/presenter-script.md`](./docs/demo/presenter-script.md)**, which
uses the versioned dataset described in
**[`docs/demo/seed-pack.md`](./docs/demo/seed-pack.md)** (profile
`thin-slice`, seed `104729`).

### API-only (in-memory DB)

```powershell
dotnet run --project src/DairyDNA.Api
# default http://localhost:5114
# GET /health
# POST /api/generation-runs
```

Web alone needs `ApiBaseUrl` pointing at the API (Aspire wires this via service discovery).

### Google Maps

The U.S. network views use the Google Maps JavaScript API. Enable that API in
a billing-enabled Google Cloud project, restrict the browser key by HTTP
referrer, and provide it to the web process without committing it:

```powershell
$env:GoogleMaps__ApiKey = Read-Host "Restricted Google Maps browser key"
dotnet run --project src/DairyDNA.Web
```

Without a key, map panels show a configuration message. Charts use Chart.js
4.5.1 and require access to jsDelivr when the page loads.

### Tests

```powershell
dotnet test DairyDNA.sln
```

Or run the lightweight CI-ish checks (build, test, secret scan, health-check
presence) via `./scripts/ci-checks.ps1`; see `.github/workflows/ci.yml` for
the same checks in GitHub Actions.

## Stack (pinned)

.NET 10 · ASP.NET Core Minimal APIs · Blazor Interactive Server · Semantic UI ·
Fluxor · Chart.js · Google Maps · .NET Aspire · EF Core · SQL Server · ML.NET ·
OR-Tools

Optimizer: OR-Tools (`ortools-cm-v1`) is the system of record since feature
009; the earlier `naive-cm-v1` remains available only via explicit
`optimizerVersion=naive-cm-v1` for regression comparison — see
`docs/architecture/adr-0001-naive-optimizer.md`.
